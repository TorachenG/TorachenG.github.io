起因很简单：作品集是 PPT，但我想在网页上看它。

一开始想直接导图片，后来放弃——那样没有文字选中、没有响应式、也谈不上「网页」。于是决定真做一次还原：读 PPTX 的 XML，按原始坐标重建 DOM。

## 一、先搞清楚单位

PowerPoint 的坐标是 EMU（English Metric Unit），1 英寸 = 914400 EMU。网页按 96dpi 算，于是：

```python
EMU_PER_PX = 9525        # 914400 / 96
x_px = emu_x / EMU_PER_PX
```

幻灯片 12192000 × 6858000 EMU，正好是 1280 × 720 px。整页按这个画布等比缩放，坐标就不用二次换算。

## 二、形状比想象中简单

这套稿子只用了 `rect`、`roundRect`、`ellipse`、`line`、`round2SameRect` 和一种自定义圆角路径。映射到 CSS 就是 `border-radius`、`clip-path` 和 SVG `line`，没有必须用 Canvas 的地方。

## 三、文字是最难的部分

字号、字距、行距都能读出来，难的是两件事：

- **字体**：稿子用的是 MiSans。我把它子集化后以 base64 内嵌，只保留用到的 259 个字符，单字重 24KB。
- **基线**：PowerPoint 的行盒高度是 `1.2 × 字号`，但首行基线位置和浏览器的 `line-height` 算法并不一致。行距越大，偏差越明显。

最后我用了一个笨办法：把每一页渲染成「纯文字 + 绿色」的图，和 PowerPoint 导出图做互相关，逐个文本框算出偏移量，再写回布局。

## 四、图片要按 srcRect 裁

PPT 里的图片经常带裁剪和透明度。直接按框拉伸会错位，必须按 `srcRect` 先裁再缩放。另外，柔化边缘（soft edge）不是 CSS 滤镜能直接模拟的，我在生成资源时把 alpha 通道按距离羽化掉了。

## 五、阴影和反射

- 阴影：形状用 `box-shadow`，图片用 `drop-shadow`，模糊半径要乘一个 0.5 左右的系数才对得上。
- 反射：`-webkit-box-reflect` 在带 transform 的容器里表现不稳定，最后改成「复制一份、垂直翻转、用渐变遮罩」。

## 六、3D 透视只能逼近

第 3、4 页的手机和视频是 PPT 的 3D 相机效果。CSS 只能近似：

```css
transform: perspective(1900px) rotateX(-3deg) rotateY(-18deg);
```

我写了个小脚本，把「透视距离」和「旋转系数」当参数网格搜索，用像素误差做目标函数，最后把误差从 38 降到 17。

## 七、验收要量化

每页都截图和 PowerPoint 导出图比对，算平均通道误差。最终结果：

| 页面 | 平均误差 |
| --- | --- |
| 第 1 页 | 3.81 |
| 第 2 页 | 2.39 |
| 第 3 页 | 7.47 |
| 全站平均 | 4.90 |

3、6、9 页后来被我改成了原生玻璃悬浮框，误差变大是故意的——那是设计升级，不是还原失败。
